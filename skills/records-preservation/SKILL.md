# Records Preservation

Read the common contract and **Preservation** stage. Verify captured bytes and exact acquisition bindings through the installed functional preserver. Retain imported originals, legacy occurrence declarations and immutable receipts. A hash match alone does not resolve missing role, scope or storage.

For imported originals, use the reviewed additive reconciliation API only when its exact source composition and installed policy are verified. Enrollment is a candidate; explicit functional acceptance is a separate operation. Do not synthesize mail provenance or treat legacy declarations as verified captures. Preservation replay can mutate intake in the baseline adapter: isolate all writable dependencies, not just the canonical ledger.

Pass the accepted preservation binding to `records-extraction`; keep unresolved declarations and compatibility holds visible.

Shared versioned inputs, outputs, retry/failure rules and Hermes release gates:
[Records stage handoff](../../docs/RECORDS-STAGE-HANDOFF.md). Read it for this stage;
use the next skill only after its eligibility conditions are satisfied. These
repository skills require that shared document to travel with the skill bundle.
