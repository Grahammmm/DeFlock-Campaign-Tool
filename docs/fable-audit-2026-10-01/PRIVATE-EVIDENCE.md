# Private evidence access and safe transfer

The public repository is sufficient to begin a code/architecture/test audit. It is not sufficient to certify SLO's operational runtime or historical corpus. Do NOT upload the raw private build brief, owner register, HTML audit, mail, originals, receipt bundles, original hashes, subscriber data, credentials, signed URLs or host configuration into this public repository.

The owner retains a secure locator map for the items below. Ask for authorized read-only access or a sanitized attestation through an appropriate private channel. Do not request passwords/tokens in chat or infer hosts/paths from this package.

Use immutable snapshots and read-only copies. Do not let audit tooling send email, replay queued external effects, publish, provision, or modify live records. Any unavoidable test write uses an isolated candidate with explicit scope. Redact third-party personal data before cloud analysis or use the permitted local route; subscriber/credential/restricted workflow data stays excluded.

For every inaccessible item, report NOT TESTED, the missing artifact, why it matters, an owner and the smallest safe next step. Lack of private access is not evidence that a feature is broken, and a public test is not evidence that the private runtime is healthy.

The local evidence map is intentionally NOT in this package. The owner can hand it to the auditor privately. Do not make up private URLs for it.
