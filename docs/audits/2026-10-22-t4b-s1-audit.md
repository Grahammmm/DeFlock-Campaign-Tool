# T4B S1 independent audit (PR #179)

- Target: PR #179, head `70adb4eeab7c395a5439bc97654322b85b854c42` (`codex/t4b-s1-policy`).
- Design: `docs/RECORDS-LEGACY-MAIL-RESOLUTION.md` (PR #151), sections 4-7 and slice 1.
- Scope: strict policy, mail-resolution reader, append-only writer. Slices 2-5 are not built.
- Method: cold read of the full diff, the PR's 20 tests (all pass), then 67 new synthetic
  adversarial tests in `tests/t4b_adversarial/` (skipped unless `T4B_ADVERSARIAL=1`).
- Data: synthetic only. No real mail, records, credentials or network. No existing source changed.
- This is an extra look, not independent review sign-off.

Reproduce (needs PR #179 files on the checkout):

    git fetch origin pull/179/head && git checkout FETCH_HEAD -- campaign_tool tests/records
    T4B_ADVERSARIAL=1 python -m unittest discover -s tests/t4b_adversarial -t .

Result on `70adb4e`: 67 run, 47 pass, 20 fail. Each failing test asserts what the design
requires and is tagged with its finding ID. Line numbers are for `70adb4e`.

## Bottom line

- No Critical or High found.
- No path found where a resolution is applied through the normal writer without the
  append-only row. The remaining gaps need DB-write or in-process access.
- 14 findings: 0 Critical, 0 High, 6 Medium, 8 Low. Fix F-01, F-02, F-03, F-06 before S2.

## Ranked findings

### Medium

**F-01 Storage root is not tied to the records root**
- Where: `original_resolution_mail.py:32-39`, `:45`
- Impact: any directory with `blobs/<sha>` and a receipt file whose hash matches is accepted
  as the home of the original. A resolution can point outside the real records root.
- Fix: pass the expected output root into `append` and the reader. Require
  `storage.parent.parent == root`.
- Confidence: High. Test: `test_storage_root_is_not_tied_to_the_ledgers_own_root`.

**F-02 Reader never proves a policy approved the row**
- Where: `original_resolution_mail.py:52-73` (`policy_sha256` is only compared to the row's own column)
- Impact: a row with a made-up policy hash is treated as resolved if the receipt file hashes
  to the receipt digest. `legacy_binding_sha256` is also never re-checked at read time.
- Fix: make the reader take the trusted policy hash (or a loaded policy) and require the
  row's `policy_sha256` and receipt to match an entry. Re-check the legacy row hash.
- Confidence: High. Needs DB write plus a file the attacker controls. Test:
  `test_reader_accepts_a_row_no_policy_ever_approved`.

**F-03 Immutability triggers can vanish unnoticed**
- Where: `original_resolution.py:34-58` (`installed`, `ensure_schema`)
- Impact: only the marker hash is checked. After `DROP TRIGGER`, updates and deletes work
  and `ensure_schema` returns happily. This was already true for v1; S1 adds a new payload
  type on top of it.
- Fix: verify the expected trigger names and SQL in `sqlite_master` on every open.
- Confidence: High. Test: `test_dropped_triggers_are_not_noticed_by_schema_check`.

**F-06 A validated policy object can be changed afterwards**
- Where: `mail_resolution_policy.py:99` (plain public `raw` and `sha256` attributes);
  writer check at `original_resolution_mail.py:80`
- Impact: after validation, `policy.raw` and `policy.sha256` can be replaced with other
  consistent bytes. The writer only checks `type(policy) is ...`, so it admits the swapped policy.
- Fix: use `__slots__` and read-only properties (or a frozen class). Re-verify the hash in `admission`.
- Confidence: High. Needs in-process access. Test:
  `test_policy_reassigned_after_validation_cannot_authorise_a_different_original`.

**F-08 Every `admission()` re-parses the whole policy**
- Where: `mail_resolution_policy.py:116-119`
- Impact: about 10 ms per call at the largest practical policy (4,000 entries). Resolving
  all of them costs about 40 s of pure parsing, inside a write transaction.
- Fix: decode once in `__init__` and return a deep copy per call.
- Confidence: High. Test: `test_admission_cost_does_not_scale_with_policy_size`.

**F-04 A failed append leaves its row in the caller's transaction**
- Where: `original_resolution_mail.py:134-138` (INSERT, then `effective_original`)
- Impact: if the final self-check raises, the row is already inserted. A caller that catches
  the error and commits would store a row the reader rejects. Rows are permanent.
- Fix: wrap INSERT plus self-check in a `SAVEPOINT` and roll back to it on any error.
- Confidence: High. Backend S2 should roll back on error, so impact is conditional. Test:
  `test_failure_after_insert_does_not_leave_a_row_in_the_callers_transaction`.

### Low

**F-05 `..` is collapsed before the symlink walk**
- Where: `mail_resolution_policy.py:47` (`os.path.abspath`)
- Impact: `link/../x` opens the lexical parent, not what the kernel means. The "no symlink in
  any component" promise does not hold for such paths. Hash pin still protects the content.
- Fix: reject any `..` or non-absolute input before use. Test: `test_dotdot_cannot_launder_a_symlinked_component`.

**F-07 Deferred transactions only fail at INSERT, uncoded**
- Where: `original_resolution_mail.py:79`
- Impact: `con.in_transaction` accepts a plain `BEGIN`. The loser gets `sqlite3.OperationalError`
  (database is locked), not a coded error. No double row. Fix: require a write lock
  (for example `BEGIN IMMEDIATE` evidence) or map `sqlite3.Error` to a coded error.
  Test: `test_deferred_transactions_lose_cleanly`.

**F-09 The 10,000-entry bound can never be reached**
- Where: `mail_resolution_policy.py:11-12`
- Impact: one entry is about 419 bytes, so 2 MiB caps `originals` near 5,000. Docs say 10,000.
- Fix: fix the doc or raise `MAX_POLICY_BYTES`. Test: `test_limits_boundaries_and_reachability` (passes; shows the math).

**F-10 Non-canonical storage paths are accepted and stored verbatim**
- Where: `original_resolution_mail.py:33-35`
- Impact: `//` and `/./` spellings of one path are accepted. Two spellings give two different
  bindings, so a replay hits `original_resolution_conflict`.
- Fix: require `str(Path(p)) == p` and `os.path.normpath(p) == p`. Test: `test_noncanonical_spellings_are_one_binding`.

**F-11 Receipt content is never parsed**
- Where: `original_resolution_mail.py:45-46`
- Impact: only `sha256(bytes)` is checked. A receipt for the wrong export would pass if the
  owner pinned its hash. Design section 7 only asks for the hash, so this is by design.
- Fix: none needed in S1. S2 must verify the receipt covers the original.
  Test: `test_receipt_content_is_never_parsed_or_tied_to_the_original`.

**F-12 Mail identity fields have no bounds or character rules**
- Where: `original_resolution_mail.py:25-28`
- Impact: CR/LF, NUL, bidi controls and 100 KB strings are accepted for `account` and
  `folder`. `uid` and `uidvalidity` accept values above 32 bits (IMAP limit). Nothing in S1
  sends or prints these, but S3 reports and any future mail output will.
- Fix: cap length, reject control characters, and cap UIDs at `2**32 - 1`.
  Tests: `test_control_characters_and_oversize_...`, `test_uid_and_uidvalidity_bounds`.

**F-13 Reader raises uncoded errors on garbage `payload_json`**
- Where: `original_resolution.py:82` (plain `json.loads`)
- Impact: deep nesting raises `RecursionError`. Bad JSON raises `JSONDecodeError` with
  uncoded text. Only reachable with DB write access. Fix: use `decode()` from the policy
  module and map failures to `original_resolution_payload_mismatch`.
  Test: `test_deeply_nested_or_garbage_payload_json_only_raises_coded_errors`.

**F-14 Stored `payload_json` text is not required to be canonical**
- Where: `original_resolution_mail.py:58` (compares the digest of the parsed payload)
- Impact: duplicate keys or whitespace in the stored text pass as long as the parsed value
  hashes right. Fix: require `row["payload_json"] == store.canonical(payload)`.
  Test: `test_stored_payload_text_must_be_the_canonical_text`.

## Verified sound (tests pass)

- Policy file loading: symlinked file, directory or root refused. FIFO, directory and device
  refused without blocking. Mode, group/world access, truncation, oversize and trailing bytes refused.
- Policy bytes: duplicate keys, NaN/Infinity, BOM, UTF-16, deep nesting, wrong types, bools as
  ints, upper-case or Unicode digits, unsorted or duplicate lists, and `held`/`originals` overlap
  all raise only `resolution_policy_invalid` or `resolution_policy_mismatch`.
- Expected hash is validated before it is joined into a path, so no traversal.
- `admission()` returns an isolated copy.
- Raw `INSERT` without the one-shot gate, wrong values, or `UPDATE`/`DELETE`/`REPLACE` are blocked.
  Subclassed or fake policy objects are refused. Held originals are not admitted.
- Concurrency: four threads give exactly one row; three get the idempotent replay. Two
  conflicting policies give one winner and one `original_resolution_conflict`.
- Crash before commit (forked child, no commit) leaves no row; retry succeeds. Crash after
  commit replays as reused. Torn or truncated receipts are caught by the reader.
- Extra occurrences of the same original, in any insert order, do not change the binding. A
  different occurrence cannot stand in for the policy's binding occurrence.
- Receipt directory or file as symlink, FIFO, directory, or over 1 MiB: refused without hanging.
- `..`, relative, NUL, upper-case, look-alike and non-string `storage_path` values refused with coded errors.
- Lone surrogates, NFC vs NFD, 1 MB strings and duplicate keys in occurrence JSON never crash the writer.
- Orphan blobs or receipts without a row grant nothing.
- By design, not defects: a self-built policy object is accepted (the class says a hash match
  does not prove approval), and a successor policy replay conflicts at the writer (the S2 plan
  must skip already-resolved originals).
