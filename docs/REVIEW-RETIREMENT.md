# Cached review retirement

Cached `challenge:*` review or test-only validation cannot retain publication authority after the factual-review repair. Both manual and unattended runs commit a root publication hold in the existing `ledger_meta` table before intake, selection limits or cancellation. This changes no ledger schema or validation grants. The existing root lock serializes retirement with owner approval, publication and rollback.

A manual run retires at most 400 current review rows. Unattended retirement uses the smaller of 400 and the configured original limit, checking its existing time/cancellation safety state before each row. Each row durably revokes bound proposal approval before controlled review/dependent invalidation. A failure stops with a fixed error; the durable hold prevents later cached approvals from publishing. Completed row transitions leave the selection queue, so another run resumes without a new cursor or rewriting history. No intake or advancement result can claim completion while retirement is pending.

Publication, new approvals and rollback refuse a pending or malformed hold. The hold is cleared only after a write-transaction recheck finds no eligible current reviews. Non-test review from other issuers is not selected and its bindings/approval remain intact. Its publication pauses while this root hold is pending. Clearing the hold does not restore approvals revoked by retirement and does not acknowledge unrelated unattended safety stops. An interrupted unattended run still requires its existing safety acknowledgement, or a separate manual retirement run; no new hold-clearing API is added.

Run a records pipeline once on an upgraded root before using publisher commands: existing roots acquire the durable hold when retirement starts. This is retirement orchestration, not a new authenticated factual-review admission interface. The synthetic non-test fixture uses installed validators and actual prerequisite bindings with fictional reviewer declarations. It proves preservation of that controller metadata, not human identity, independent review of originals, OCR fidelity or legal acceptance.

Tests in `tests.records.test_review_retirement` cover failure, deadline, cancellation, crash/retry, rollback and non-test authority preservation. `python -B -m tests.records.retirement_boundary` is the explicit large Linux acceptance test: 10000 then 10001 actual protected test-only SQLite review rows, no mocked population or disabled triggers, 400-row retirement followed by bounded resumption and retained history. It is separate from earlier mocked-population probes and default small-test discovery.
