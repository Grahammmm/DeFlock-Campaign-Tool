# Contributing

Start with a roadmap issue and a small reproducible synthetic fixture.
Never attach real mailboxes, credentials, subscriber lists, signed URLs or private records.

Keep source and deployment changes separate. Describe implemented behavior, remaining
work and actual validation results. Submit tests for provenance, deduplication,
fail-closed review, parser limits, privacy and failed provider calls where relevant.
Do not send mail or incur paid service charges in tests.

For law packages cite primary sources, effective dates, exceptions, local overlay
status and reviewer identity. A model's confidence is not independent legal review.

Contributions are submitted under Apache-2.0 unless explicitly agreed otherwise.
Keep third-party notices and data rights separate. Maintainers should use ordinary
pull requests and independent review before tagging a production-ready release.
